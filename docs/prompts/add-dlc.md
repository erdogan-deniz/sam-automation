# РОЛЬ
Ты — мейнтейнер репозитория sam-automation. Сессия — РЕСЁРЧ будущей фичи
auto-add DLC (добавление бесплатного DLC в библиотеку для игр, которыми
пользователь уже владеет). Только Windows, Python 3.12, venv в `.venv`.
Отвечай коротко. **Это не TDD-сессия с порога** — сначала нужно выяснить,
работает ли сама идея, потом решать, строить ли фичу (superpowers:
brainstorming, путь spike: вопрос выполнимости → дешёвая проверка живьём →
отчёт → решение, ДО любого кода на постоянку). Если ресёрч подтвердит
выполнимость и решено строить — тогда обычный процесс: TDD, гейты
(`ruff check .`, `ruff format --check .`, `mypy app`, `pytest tests/unit -q`),

# ЗАДАЧА / ГИПОТЕЗА
Источник — R-6 в `docs/backlog.md`. `add_free.py`/`add_demos.py` уже умеют
добавлять в библиотеку бесплатные игры/софт/демо через
`client.request_free_license`. Гипотеза: тот же CM-вызов способен выдавать
и бесплатный DLC для игр, которыми аккаунт уже владеет — но это НЕ
проверено. Открыты РОВНО два вопроса, и оба надо закрыть ДО дизайна фичи:

1. **Работает ли `request_free_license` для DLC?** Или для DLC нужен другой
   вызов/другая семантика (напр. требование, чтобы CM-клиент уже видел
   лицензию на базовую игру в `client.licenses`, иначе `EResult`
   отличается от кейса F2P/демо)?
2. **Как обнаруживать кандидатов?** У F2P/софта/демо — browse всей витрины
   по `category1` (998/994/10, см. `app.steam.store_search`). DLC ТАК не
   листается — Steam Store не отдаёт «все DLC каталога» одним category-поиском
   (DLC привязан к конкретной базовой игре). Вероятный путь — по каждой
   игре из библиотеки (`all.txt`/`client.licenses`) дёргать
   `ISteamApps/appdetails` или `dlc`-поле в её данных, собирать список DLC
   appid, дальше фильтровать по цене (только бесплатные). При библиотеке
   в тысячи игр (см. `data/games/ids/all.txt`) это может быть тысячи
   HTTP-запросов — нужно живьём оценить объём/скорость/рейт-лимит ДО
   решения строить фичу как есть.

Отчёт — что живой прогон реально показал (реальные EResult, реальная форма
appdetails-ответа, оценка числа запросов), а не теоретические рассуждения.

# ОГРАНИЧЕНИЯ / РИСКИ
- **`request_free_license` необратим на аккаунте** (штатно лицензию не
  снять) — тот же риск, что у add_free.py/add_demos.py, но здесь ЕЩЁ не
  проверено даже, что вызов делает на DLC-appid. НЕ вызывай без явного
  запроса пользователя, и НЕ на произвольном DLC — только на заведомо
  бесплатном (платный DLC через этот путь трогать нельзя даже в
  вероятность, это может значить попытку купить/что-то испортить —
  сначала на 100% убедись, что конкретный appid бесплатен).
- Только Windows; реальный прогон требует живого Steam CM-логина.
- Объём: библиотека пользователя — тысячи App ID (`all.txt`). Naive
  per-game appdetails-обход без рейт-лимитинга может быть медленным или
  словить троттлинг — не проектируй фичу «в лоб» без предварительной живой
  оценки стоимости (см. МЕТОД п.3).
- Не выдумывай API/поля Steam, которых не видел в реальном ответе — если
  появилась гипотеза о форме ответа appdetails/CM — проверь живьём, потом
  пиши в код/докстринг.
